Concept 4 of 6

Failures that become retrievable

Most harnesses record that something broke. This one records what kind of thing broke, so the next occurrence is cheaper.

The loop

build ──> test ──> fail ──> extract ──> vectorize ──> store
  ▲                                          │
  └──────────── retrieve on next failure ─────┘

What "extract" means here

Not the stack trace. The shape of the failure — which assertion, in which file class, matching which previous incident. A pattern that cannot be retrieved is a log line; one that can be retrieved is a fix waiting for a match.

// the only part that is really load-bearing
let past = index.query(embedding(failure))?;
if past.len() > 0 { context.push(past[0].fix) }
